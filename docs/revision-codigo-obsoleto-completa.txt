La intuición de “muchas cosas que no se usan, parches sobre parches, funciones
repetidas con otros nombres y parámetros repartidos” encaja con el estado del repo.

  HMI backend
    - state.py (~5017 líneas) y cycle.py (~5280 líneas) concentran casi todo.
    - Catálogo de errores EXXX duplicado; dos fórmulas de progreso de lote.
    - Varios wrappers TCP/API sin uso; nombres confusos (“error policy” x2).

  HMI frontend
    - Recuperación/purga de lote duplicada en MaquinaTab y CycleTab (~150+ líneas
      cada uno) con deriva ya visible entre tabs.
    - API muerta (resetCycle, getCycleConfig, getAppConfig); reset real vía
      resetError con handler mal nombrado resetCycleCmd.
    - ~178 de ~553 claves i18n sin cablear; tema oscuro e i18n EN preparados
      pero inactivos; flags CAN en Motion siempre false en el mapper.

  Firmware
    - EspLink común, pero hold/TCP flush y parsers JSON copiados en cada .ino.
    - PreFeeder Master vs esclavo: dos fuentes de verdad (comandos, fallos,
      enums SystemFault distintos); posible bug en FAULT_OPERATOR → wire 0.
    - plcStateName/motStateName en headers sin uso; switches locales duplicados.

  Repo y docs
    - PreFeeder/tools: ~92 MB (arduino-cli duplicado + zip); sin referencias fuera.
    - docs/README.md: estructura HMI desactualizada (rutas y nombres de config).

No hay TODO/FIXME en .py del backend HMI (grep vacío).

1. SEÑALES DE “PARCHE SOBRE PARCHE”
================================================================================

1.1 Dos capas llamadas “política de error”
  - core/error_policy.py → clase ErrorPolicy (latch EXXX para snapshot/API).
  - cycle.py → CycleRunner.apply_error_policy() (pausa secuencia / hold del lote).
  - core/state.py encadena: _error_policy.set_error y luego puede llamar
    _cycle.apply_error_policy(ui).
  Mismo término, dos responsabilidades; confunde lectura y onboarding.

1.2 Catálogo EXXX en dos sitios (solo uno manda en runtime)
  - HMI/machine_states.py líneas ~18-33: CYC_ERR_*, MAIN_ERR_*, ANDON_ERR_*.
  - HMI/core/error_catalog.py: tabla _ROWS con mismos bytes y slugs.
  Evidencia: rg CYC_ERR_|MAIN_ERR_ en *.py → solo machine_states.py y strings
  en error_catalog.py; ningún import de esas constantes desde machine_states
  para resolver errores. Quien manda: lookup(), format_ui(), ErrorPolicy.

1.3 Dos fórmulas de progreso de lote
  - cycle.py: _set_progress (~2357-2359): ((rep-1) + step/PROGRESS)/total.
  - core/state.py: _cycle_live_progress (~4012-4018): incluye (step-1 + intra).
  UI mezcla cycle_snap["progress"] con recálculo en HmiState → % puede divergir.

1.4 Migración legacy activa (no es dead code, pero infla cycle.py)
  - LEGACY_*, migrate_legacy_config_files() en cada load/save de config.
  - Migra/borra config/cycle_config.json y app_config.json viejos hacia
    config/cycle.json, etc.

1.5 Dos endpoints HTTP → misma función backend
  - app.py: POST /api/cycle/reset y POST /api/error/reset → get_state().cmd_error_reset().
  - Frontend: resetCycle() → /api/cycle/reset (sin consumidores).
  - useHmiState resetCycleCmd → api.resetError → /api/error/reset (confirm: true).

1.6 Build frontend con reglas distintas
  - app.py ensure_frontend_dist / frontend_dist_is_stale: rebuild si src > dist.
  - iniciar_hmi.py _build_frontend_if_needed: solo si falta dist/index.html.
  Variable: HMI_AUTO_BUILD_UI (default rebuild en app.py).

1.7 Puntos de entrada HMI (todos válidos, documentación debe aclarar)
  - HMI/iniciar_hmi.py — canónico operador (bat, ps1).
  - HMI/scripts/iniciar_hmi.py — execv al launcher raíz (compatibilidad).
  - python app.py — systemd tcm-hmi.service, desarrollo.
